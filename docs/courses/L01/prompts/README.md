# L01｜一个案例、三次 Codex 交互

本目录用于课后实践。先通过讲义回答三问：为什么需要个人工作台、怎样协同 Codex 改善交付质量、应该怎样设计。学生先写个人设计，再通过同一案例的三次交互，把设计变成可验收的 V0.1，并用运行证据检查设计。

课程建设主线：

> 学员先使用 Codex，逐步搭建自己的个人 AI 研发工作台；再通过“工作台 + Codex”的协作方式，持续开发并交付 FlowERP。

| 顺序 | 实践动作 | 文件 | 本步产物 |
|---:|---|---|---|
| 1 | 审查个人设计，访谈并冻结范围 | `01-访谈并冻结范围.md` | 三问的设计依据、四项决定与种子 Spec |
| 2 | 发起受控实现 | `02-受控实现WorkbenchV01.md` | 首次红灯、最小实现与 Diff |
| 3 | 复验并完成自举 | `03-复验并完成自举.md` | 绿灯、自举记录与人工签收 |

第二次交互先只生成测试，由学生核对并保存有效红灯，再授权实现。第三次交互回到个人设计，区分哪些能力已经验证、哪些尚未实现。完整课后实践不压入 30 分钟线上精讲。

课堂边界：L01 不开发 FlowERP 业务功能；FlowERP 在 L04 才作为客户项目首次接入工作台。三次交互不能替学生作范围决定或最终签收。
