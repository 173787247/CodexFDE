# L01｜以终为始：一次可验证的 AI 交付怎样完成？

首先交付个人研发工作台，再通过持续开发 FlowERP 验证它的价值。FlowERP 是这一过程中的伴生客户产品。阅读时围绕工作台的必要性、协作方式与设计展开。

本讲以 V0.1 自身建设贯穿阅读与实践：代码跑通后还需核对要求与结果，所以先建设可追溯的记录层，再用自举验证它。FlowERP 截图集中展示课程最终目标。

| 顺序 | 材料 | 怎样使用 |
|---|---|---|
| 1 | [阅读讲义](./阅读讲义.md) | 看成果截图，理解问题、协作机制和设计理由 |
| 2 | [实践操作手册](./实践操作手册.md) | 在自己的隔离区按步骤实现并核对结果 |
| 3 | [提交模板](./SUBMISSION.md) | 按手册复制填写，索引真实运行记录，最后完成复核 |

阅读讲义先连续解释成果、问题、协作与设计，再进入实践和复验。截图用于观察参考成果，自己的实现按实践手册完成。线上精讲原则上不超过 30 分钟，实践可分次完成。

本讲交付：个人设计、本人签署的需求说明、Workbench V0.1 五个操作及其建设证据。FlowERP 本讲用于观察最终产品；L04 才首次通过工作台开发库存导出。

配套：[L00 环境准备](../L00-课前准备-安装工具与通过环境自检.md) · [行动卡](./行动卡.md) · [课堂 PPT（图解版）](<./slides/L01-以终为始：一次可验证的AI交付怎样完成？-图解版.pptx>) · [前一录课版](<./slides/L01-以终为始：一次可验证的AI交付怎样完成？-录课版.pptx>) · [原课堂 PPT](<./slides/L01-以终为始：一次可验证的AI交付怎样完成？.pptx>) · [Codex 交互提示词](./prompts/README.md)。

图解版保留 22 页，参考李宏毅 MLDS 和 Stanford CS230 的教学形式，采用同图递进、实例对照与案例后归纳。课件与讲义都用 V0.1 的持久保存、重复编号和自举贯穿；FlowERP 用于目标定位。讲解提示见逐页备注，教学情境与实验预期均需由自己的实际运行验证。

`tools/` 是课程提供的跨平台证据采集支架，只保存命令结果、时间和退出码，不实现学生的工作台，也不代替人工审核。图片直接嵌在阅读讲义中，使用本目录的[截图资源与来源说明](./assets/final-deliverables/README.md)；分享时请保留本目录结构。
