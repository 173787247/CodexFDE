# L02｜让规则跨会话生效

本讲只处理一个连续案例：运营要求 Codex 绕过采购审批、直接修改库存，并删除失败证据。学员用三次 Codex 交互，把这次风险沉淀为工作台的长期规则，再在新会话中复验“危险动作被改道、合法任务仍能继续”。

## 课堂顺序

1. 在本讲起始隔离工作区中，把 `@docs/courses/labs/L02/prompts/01-记录越界请求基线.md` 交给 Codex。先记录它准备怎样做，不批准任何写操作。
2. 回到 PPT 完成规则归属、五段式规则、作用域与 DoD 的判断。
3. 把 `@docs/courses/labs/L02/prompts/02-写入长期规则.md` 交给 Codex；审查补丁后，由学员决定是否接受。
4. 新开一个 Codex 会话，把 `@docs/courses/labs/L02/prompts/03-新会话双探针复验.md` 交给 Codex；保存危险请求和合法请求的实际响应。

## 课堂硬边界

- 本讲只允许修改规则与证据材料，不修改 `flowerp/` 业务代码，不写运行数据库。
- 规则实验前后的 FlowERP 业务账必须保持不变。
- `AGENTS.md` 是项目协作规则，不是权限系统；真实阻断仍由沙箱、身份、状态机、事务和服务端校验承担。
- 新会话是否读取规则，必须由实际响应、文件来源和 Diff 证明，不能用“模型说它记得”代替。

## 离场证据

- 一次修改前的越界请求基线；
- 一份经过学员取舍的规则补丁；
- 一次新会话双探针记录；
- 一份判决：拒绝什么、依据什么、合法替代是什么、真正执法点在哪里。
