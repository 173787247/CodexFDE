# 工作台事项与决策

事项先说明“为什么值得做”，课程任务再说明“本次允许怎么做”。在工作台左侧打开“事项与决策”，可保存客户原话、来源、具体问题、期望结果、非目标、验收标准与已有证据。

## 使用步骤

1. 填写自己的署名，选择“记录新事项”。保存后，事项写入工作台的 workbench.db；刷新或重新打开可以查回。
2. 补充实际观察。进入交付准备需要具体问题、证据、目标、项目与验收标准；涉及库存、金额或权限时还需要验收负责人。
3. 保存修订后，选择进入交付准备、暂缓或不做，并说明理由。暂缓必须说明再评估条件。
4. 决定保存后保留版本和署名，页面转为只读。事项决定不是代码执行授权，也不是产品验收。
5. “核对课程交付方案”带入摘要，随后仍须选择讲次、核对合同。L04～L14 的代码执行采用本讲固定合同，不能把任意事项摘要当作已绑定的实现 Spec；L15/L16 从已决定事项生成具体六段式 Spec，另需新增检查与起始基线；不关联事项时可单独提交具体 Spec。

## 教学使用

该页面用于练习需求判断与责任记录。学生应保留原话、证据、首次判断和修订原因，再对照 FlowERP 的问题确定工程任务。不能因为选择“进入交付准备”，就声称已经实现功能或通过验收。

当前页面复用事项记录模型。L15/L16 代码方案绑定事项版本、决定人、需求内容指纹和冻结合同指纹，授权时重查事项，任务创建后双向记录关联，再进入隔离执行。重复事项方案、变更版本或不一致的任务合同会被拒绝。已关联事项可返回任务详情；L04～L14 固定合同不接受任意事项冒充实现范围。关联与合同传递已用合成测试验证，不代表真实新增 ERP 需求已经交付。修改后的服务器需要重新加载才会提供新接口；仅刷新前端不能更新运行中的 Python 服务。
